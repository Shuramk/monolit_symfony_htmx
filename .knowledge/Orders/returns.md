# Возвраты: заявки и приёмка

Первый этап реализован 2026-10-16. Запись только в app, legacy только SELECT.
Спецификация: [order-returns/spec.md](../spec/order-returns/spec.md).

## Реализованные слои

- Миграция `Version20261016150000`: заявки, позиции, возвраты, маркер импорта и право 115.
- `OrderReturnImportRepository` и команда `legacy:import-order-returns`: однократный
  импорт с отчётом, повтор без перезаписи. Миграция и импорт применены к локальным app/test.
- `OrderReturnRepository`: цены/отгрузки/pending, запись, пакетная загрузка позиций,
  активные списки и архив с пагинацией по 50.
- `OrderReturns`: создание заявки и атомарная приёмка с UUID, версией и блокировками.
- `OrderReturnsView`, `OrderReturnsPageDto`, `OrderReturnFormDto`: представления страниц.
- `OrderReturnsController`, Twig и Stimulus: формы, выбор заказа, создание заявки,
  приёмка, архив, предупреждения об исходных данных и история в карточке заказа.
- HTTP, functional и JavaScript tests: ограничения, повторы, права, откат,
  точность, импорт и межсоединительная блокировка заказа.

## Маршруты и права

| Маршрут | Право |
| --- | --- |
| GET /warehouse/returns | 102 или 114; каждый раздел показан только со своим правом |
| GET /warehouse/returns/archive | 114 |
| POST /warehouse/returns/drafts | 114 + 115 |
| GET /warehouse/returns/select-order | 102 + 103, Main/Sales/Production |
| GET /orders/{id}/returns/new | 102 + 103, Main/Sales/Production |
| POST /orders/{id}/returns | 102 + 103, Main/Sales/Production |

Пункты меню legacy 102/114 ведут в новый список. После приёмки пользователь
с правом 220 переходит в карточку, остальные — в список возвратов.
POST используют общий сессионный CSRF и RequestDtoParser, SQL в Repository.

## Инварианты

- Только отгруженный остаток минус pending; проведённые уже включены в отрицательные отгрузки.
- Отменённый заказ запрещён. Разные цены одного товара запрещены, одинаковые агрегируются.
- На приёмке приход только в Цех; позиции заказа, предоплата, отгрузки и статус не меняются.
- Блокировка заказа до начала consistent reads защищает расчёт на MariaDB REPEATABLE READ.
  Затем блокируется заявка и товары по ID. Версия заказа повышается.
- Точный повтор UUID возвращает ID до проверки старой версии; другой запрос с этим UUID запрещён.
  Создание заявок сериализуется по автору. Уникальные UUID и draft_id дополнительно защищены БД.
- Заявка может отличаться от фактически принятого состава; успешная приёмка закрывает её один раз.
- Весь приход, история, закрытие заявки и изменение версии откатываются при любой ошибке.

## Импорт

5354 возврата, 6059 позиций, 1282 заявки. Исторические цены/суммы/даты/авторы/ID
сохранены, nullable автор проведения определяет pending даже при нулевой сумме.
Нет повторного изменения остатков, отгрузок, предоплаты, оплат или истории.
Повтор возвращает сохранённый отчёт. Запись до завершения импорта заблокирована.

Отчёт содержит отсутствующие связи и ID заявок с некорректными позициями.
23 такие позиции сохранены в исходном payload, не преобразуются в фиктивные товары;
заявки видимы с предупреждением. Недостающие имена отображаются как исходный ID.
Исторически закрытые заявки не связываются с возвратами догадками.

## Не реализовано на этом этапе

Проведение по кассе, отрицательная отгрузка, уменьшение заказа/предоплаты,
возврат только денег, отмена принятого возврата. Кнопок этих операций нет.
Это следующий отдельный контракт, не скрытая часть текущей приёмки.

## Проверки

Связанный расширенный набор на момент реализации: 32 PHP tests / 390 assertions,
включая регрессию карточки, склада и отгрузок; JavaScript tests — 72/72. Twig, container lint,
production cache clear и asset-map:compile проходят.
В полном PHP-наборе (266 tests) остаются отдельные проблемы старого login redirect,
фиксированного счётчика каталога и ProductMappingTest; они не исправлялись в этом этапе.
На локальном PHP 8.4 проверен синтаксис основных новых файлов; запуск БД-тестов
на нём невозможен без pdo_mysql (установлен только pdo_pgsql). Runtime-проверки
выполнены на рабочем PHP 8.5. Время приёмки и складской истории единое, Europe/Kyiv;
опциональный параметр WarehouseRepository::record не меняет старые вызовы.
