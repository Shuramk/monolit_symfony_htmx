# Orders: карточка заказа

## Реализовано

- `GET /orders/{id}` защищён тем же legacy-правом `did=220`, что и журнал.
- Данные читаются из application database через OrderViewRepository, не из legacy.
- В карточку входят шапка, позиции, итоги оплат/доставки, заказчик, адрес, статус
  и история работы с заказом (без отдельной колонки статуса).
- Полнота отгрузки считается по order_shipment_items/order_shipments.
- Снимки создания/редактирования в журнале раскрываются по сообщению события,
  по умолчанию свёрнуты; при редактировании сначала показываются изменения.
- Деньги считаются fixed-point decimal значениями; `float` не используется.

## Оформление карточки

Ориентир — legacy templates/order_in_detail.tpl и предоставленные скриншоты.
Рабочая область 1250px (max-width: 100%), Arial 16px, line-height 21px;
breadcrumb 18px, заголовки разделов жирные 13pt. Изменения локальны для
.legacy-order-card и не меняют типографику списка/редактирования.
В заголовке «Заказы» — синяя ссылка #08f без подчёркивания на /orders;
разделитель и «Заказ №…» остаются чёрными, как в оригинале.

Ссылка редактирования находится в правой части шапки, а не отдельным абзацем.
Таблица: colgroup для номера/количества/цены/суммы (30/160/140/140px),
семантические th, градиент шапки, чередование строк; цена/количество по центру,
суммы справа. Единица измерения отображается у количества, не дублируется в названии.
Итоговая подпись и сумма разделены по колонкам.

НДС/ФОП отображаются по сохранённому orders.markup:
- 0: базовая цена (4 знака), без дополнительной колонки и строк БН;
- 20: рядом «с НДС» (3 знака), стоимость продукции остаётся без НДС;
  под итогом продукции — «Бн 20%» и «Итого с бн»;
- 1–19: рядом «с наценкой ФОП» (4 знака) и пояснение с процентом;
  стоимость/итог продукции уже включают ФОП из общего калькулятора, повторно не начисляется.

DTO содержит markup, vatAmount и goodsTotalWithMarkup. Денежные операции — Decimal.
Блок продукции показывает итоги продукции, доставка остаётся отдельным блоком:
её стоимость включает применимую наценку/НДС, при НДС подпись «Стоимость доставки с бн».
«К оплате» по-прежнему учитывает продукцию, доставку и обе оплаты.
Сумма отгруженного включает ФОП/НДС при соответствующем режиме.
OrderDetailsViewTest проверяет три режима с доставкой, частичной отгрузкой и оплатами;
отрисовка проверяет условную колонку и строки БН.

Оплаты и доставка используют одинаковую сетку 200+140px и выравниваются с правым
краем суммы в таблице; прежнего отдельного ограничения 900px нет.
Заказчик слева, статус справа в той же строке (колонка 280px); телефон — tel-ссылка.
История имеет колонку даты 245px и показывает секунды, как original time_format.
На узком экране блоки становятся вертикальными, таблица прокручивается внутри
своего контейнера (min-width: 1150px), а не расширяет всю страницу.

Это только представление существующих данных. Расчёты, сущности и запись не менялись;
не добавлялись фиктивные кнопки оплат и другие неперенесённые функции.
Рабочая печать заказа перенесена отдельно: [printing.md](printing.md).
OrderControllerTest проверяет структуру, размещение ссылки редактирования, итоги,
блок статуса, журнал и 404; раскладка дополнительно проверена в Chrome.

## Вес и склад

- Справа от стоимости — «Вес» (80px) и «Склад*» (280px), с рамкой и легендой как в legacy.
- Вес строки в тоннах = вес единицы группы в кг × заказанное количество / 1000.
  BigDecimal сохраняет точность; 3 знака показываются у строки и общего веса,
  итог округляется только после суммирования неокруглённых весов.
- Склад — только `storage_workshop` (цех), не сумма цеха/офиса/третьего склада.
- Зелёное число = цех минус открытые задачи отгрузки (`type=2`, `status=0`),
  отрицательные значения не скрываются.
- Синее число = неотгруженное количество открытых заказов
  (`new`, `in_progress`, `ready_for_shipment`, `partially_shipped`), включая текущий.
  Заказ и отгрузки предварительно агрегируются по заказу/продукту;
  закрытые заказы и нулевые/отрицательные остатки не резервируются.
- По синему числу раскрывается таблица заказов: номер-ссылка, желаемая дата доставки,
  остаток количества. Используется существующее поведение складских подсказок:
  кнопка, Escape, закрытие снаружи, позиционирование в пределах экрана.
- Выключенные продукты существующего заказа не пропадают; отсутствующий продукт
  показывается с «—» вместо выдуманного нулевого остатка.
- Данные всех продуктов карточки читаются пакетно через WarehouseViewRepository,
  без SQL в контроллере и без запроса на каждую строку. Миграция/импорт не нужны.
- Проверки: OrderDetailsViewTest (включая дубли, несколько отгрузок, выключенные товары,
  отрицательный свободный остаток, точный общий вес), HTTP-карточка и JS-подсказки.
