# Редактирование заказа

Оригинал: `admin.php?did=230&orderID=...`; сохранение: `did=231`,
`Order::save_edited_order()`, `templates/order_editor.tpl`.

Symfony: `GET /orders/{id}/edit`, `POST /orders/{id}` (JSON).
Ссылка находится в карточке заказа. Используется общая форма продукции создания:
группа, вариант, количество, цена, ФОП/НДС, скидка, сумма, удаление/добавление строк.
Ни покупатель, ни платежи/отгрузки этим действием не изменяются.
Доставка: стоимость, адрес, дата; также комментарий.
Оформление унифицировано с созданием и карточкой: Arial 16px/21px,
breadcrumb 18px с синими ссылками, общий редактор продукции, заголовки разделов 13pt.
Заказчик выводится компактным dl с tel-ссылкой; редактирование покупателя не добавлено.
`_delivery_fields.html.twig` используется и редактором, и вторым шагом создания:
дата/стоимость в двух колонках, адрес/комментарий на всю ширину блока (max-width 900px).
На узком экране поля в одну колонку, таблица продукции прокручивается внутри контейнера.
Кнопки общего оформления; «Отмена» возвращает в карточку без сохранения.
Селекты и числовые поля строки продукции имеют общую высоту 28px (border-box),
шрифт и внутренние отступы; правило общее для создания/редактирования, не затрагивает БН.
Перевозчик, число ходок, договоры и общая скидка legacy пока не моделируются
новой базой и этим шагом не перенесены; скидки позиций применяются к цене.

## Слои

- `OrderViewRepository::findForEdit()`: DBAL-чтение формы вместе с чтением списка и карточки. `OrderRepository`: загрузка и
  запись Order/OrderItem через EntityManager, сохранение исторических названий.
- `OrderEditView` / `Dtos/OrderEditViewDto`: подготовка формы, в том числе недоступных
  или потерявших связь со справочником старых товаров.
- `UpdateOrderDto` автоматически разбирается общим RequestDtoResolver; вложенные
  `UpdateOrderLineDto`, ограничения — валидатором. JSON и CSRF — существующий middleware.
- `UpdateOrder`: транзакция, загрузка сущности с коллекцией OrderPayment под блокировкой, заполнение DTO.products
  одним ORM-запросом ProductRepository::getByIds() (сущности Product), вызов Order::update(),
  сохранение и changelog. Сборка позиций, исторические снимки, проверка принадлежности,
  версия/ограничения, Decimal, скидки и обновление состава/доставки — внутри Order/OrderItem.
  В контроллере нет SQL, парсинга тела или ручного CSRF.

## Правила

- Номер, заказчик, исходные названия сохраняются. Для действительно нового товара
  читается активный справочник; прежний отключённый товар можно оставить.
- `lineId` проверяется на принадлежность заказу и повторения; `0` означает новую строку.
  `productId=0` допустим только для существующей позиции с NULL product_id.
  ID сохранённых позиций не меняются; удаляются только действительно удалённые строки.
- БН нельзя изменить после оплат (проверяется на сервере, не только disabled-селектом).
  Правило проверяет Order::hasPayments(): положительная предоплата либо любой
  положительный платёж в коллекции. Флаг из use case больше не передаётся.
- Отменённые заказы нельзя редактировать, остальные статусы и оплаты/отгрузки сохраняются.
  Legacy не запрещал изменение состава уже отгруженного заказа; новый запрет здесь
  не вводится. Будущие операции отгрузок потребуют согласования инвариантов.
- `orders.edit_version` предотвращает перезапись устаревшей формой: конфликт — HTTP 409.
  Все будущие операции изменения редактируемых данных должны увеличивать эту версию.
- Сохранение без изменений не увеличивает версию и не засоряет журнал.
- Цены пересчитываются с Decimal; скидка при загрузке равна 0, поскольку текущая
  order_items хранит уже конечную цену. Повторная скидка не применяется сама собой.

## Журнал

Событие `updated`, сообщение «Заказ редактировался».
JSON содержит новый снимок и `context.before` — полный снимок до изменения.
По раскрытию сообщения показывается только список изменений: добавлено, удалено,
изменены количество/цена, адрес, дата, доставка, БН, комментарий, итог и другие поля.
Ниже — отдельно свёрнутый «Полный снимок» с блоками «До изменения» / «После изменения»
и одинаковыми отступами. Создание по-прежнему показывает полный состав без diff.
`OrderChangelogChanges` готовит текст в read model, Twig экранирует его.
Новые снимки дополнительно сохраняют lineId для сопоставления повторяющихся товаров.
Старые JSON без lineId поддерживаются: сопоставляются товары и прежде всего
неизменившиеся повторяющиеся строки, перестановка не создаёт ложные изменения.
Снимки и изменения заказа записываются одной транзакцией: ошибка журнала откатывает всё.

Миграция `Version20261007130000` добавляет только edit_version в app-базу.
Импорт не запускается, legacy остаётся только для чтения.
