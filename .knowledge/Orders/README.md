# Orders

Рабочая папка миграции домена заказов из legacy Monolit в Symfony + HTMX.

Верхний пункт меню «Заказы» (division 200) и подпункт списка (220) ведут
на Symfony `/orders`, а не в legacy admin.php. Проверка доступа к списку остаётся по division 220.

## Текущее состояние

Чтение через DBAL из новой app-базы:

- журнал заказов;
- поиск по номеру, клиенту, телефону и статусу;
- карточка заказа;
- позиции, суммы, скидка/наценка, предоплата и платежи;
- история работы с заказом;
- вычисление актуального статуса без записи в legacy.

Создание и редактирование, включая позиции и цены, работают через Doctrine-сущности
Order/OrderItem. Changelog и заказ сохраняются общей транзакцией.
Legacy используется только для чтения и сверки оригинальной логики.

Заголовки списка, карточки, создания и редактирования используют общий класс
legacy-order-breadcrumb: жирный текст, разделитель » и одинаковая структура ссылок.
В списке — «Заказы » Список заказов» (18px, синяя ссылка по оригиналу),
в карточке — «Заказы » Заказ №…» (18px, синяя ссылка «Заказы» без подчёркивания,
остальная часть заголовка чёрная).

## Ещё не перенесено в Symfony

- перевозчик, число рейсов и укладчик в модели заказа — обязательный незакрытый пункт ниже;
- создание и отмена отгрузок;
- платежи и касса;
- кассовое проведение возвратов и возврат денег; заявки и приёмка товара уже
  перенесены — см. [returns.md](returns.md);
- изменение складских остатков;
- фактическая смена статуса заказа.

Эти операции будут переноситься только после фиксации транзакционных границ и reconciliation-проверок.

## Обязательный хвост: перевозчик и укладчик

Печать реализована частично относительно оригинала: отсутствие этих данных — не отказ
от функциональности. Задачу нельзя считать закрытой до выполнения пунктов ниже.
Это обязательная проверка перед переключением на production, не необязательное улучшение.

- [ ] Сверить legacy `carrierID`, `shippingCount`, `stackerID`, связанные справочники
  и правила самовывоза/доставки в карточке, редакторе и печатной форме.
- [ ] Добавить данные и связи в новую модель заказа, миграции и импорт существующих
  заказов/справочников. Legacy остаётся только источником чтения; старые номера заказов сохраняются.
- [ ] Добавить выбор и сохранение перевозчика, количества рейсов и укладчика при
  создании/редактировании; включить изменения в changelog.
- [ ] Вывести данные в карточке и печати; вместо временной строки «Доставка, 1 усл.»
  использовать реальные данные там, где это предусмотрено оригиналом.
  Условия ответственности за доставку выводить по фактическому виду доставки.
- [ ] Покрыть тестами самовывоз, доставку с несколькими рейсами, отсутствие укладчика
  и исторические заказы с отсутствующей записью справочника. Сверить импорт и печать с legacy.

Связанная реализация и текущие ограничения: [printing.md](printing.md).
