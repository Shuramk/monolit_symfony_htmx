# Пользователи: роли и числовые права

2026-10-11. Legacy только для чтения; управление изменяет identity_* в новой базе.

UserRole — строковый enum: ROLE_MAIN, ROLE_SALES, ROLE_PRODUCTION,
ROLE_SHIFT_SUPERVISOR, ROLE_PARTNER. Один пользователь — одна роль; отсутствие
роли — null. User хранит nullable enum в identity_users.role, без номеров групп.
LegacyUserRoleMapper на границе импорта переводит 1/2/3/10/99 в соответствующие
роли; 0, 1000 и неизвестные номера — в null (fail closed).
Version20261011180000 переводит уже импортированных пользователей без повторного
импорта и без изменения прав, паролей или сессий. legacy_group_id остаётся только
метаданными импорта, не участвует в авторизации и не редактируется новым UI.

Роль не предоставляет числовых прав автоматически, ROLE_MAIN не имеет hierarchy.
Числовые права identity_permissions / identity_user_permissions сохранены, связанные
права раскрываются существующим LegacyPermissionExpander при сохранении.

User.canAccess проверяет enabled и наличие роли. UserChecker запрещает вход без роли;
ActiveSessionSubscriber закрывает уже открытую сессию. Voter и репозиторий меню
также закрывают доступ при отсутствии роли/отключении, даже если права записаны.
При сохранении «Нет группы» все сессии пользователя отзываются в той же транзакции.
Смена рабочей роли меняет Symfony roles и требует повторного входа пользователя.
Прежние специальные условия склада сохранены, но не обходят отсутствие роли.

Настройки → Пользователи: /settings/users (1001), просмотр редактирования (1002),
сохранение (1003), создание требует 1002+1003, смена пароля существующего
пользователя дополнительно требует 1050. Контроллер в папке Identity, SaveUserDto
по типу, общий CSRF, JSON через существующий json-form.
Сохранение блокирует пользователя, валидирует роль и права, атомарно заменяет права.
SaveUser обслуживает создание и редактирование: имя, уникальный логин, роль,
доступ, права и стартовая страница. Пароль хранится только как Argon2id-хеш;
при создании обязателен, при редактировании пустой пароль сохраняет старый.
Пароль минимум 8 символов, с подтверждением. Смена логина/пароля и запрет доступа
отзывают сессии атомарно. Создание использует identity_user_numbers, без гонки MAX+1;
импортированные ID не меняются. Изменения профиля выполняются методами User.
Права отображаются в таблице шириной 500px: разделы сворачиваются, все функции
внутри раздела имеют один визуальный отступ, как в старой форме. Чекбоксы и
переключатели вложенных строк смещены на 10px. Логические связи legacy parent/sub_parent
сохранены для назначения прав. Выбор родителя включает потомков,
выбор потомка включает его предков. Числовые ID доступны в title, не загромождают UI.
Выбор стартовой страницы включает её право и предков, но не дочерние действия.
В форме показано название выбранной стартовой страницы; варианта «по умолчанию»
нет. Без выбора кнопка сохранения заблокирована, DTO и SaveUser также отклоняют
отсутствующий, нулевой или недоступный раздел. Снятие соответствующего права
сбрасывает выбор и снова блокирует сохранение. Все разделы изначально свёрнуты.
Для стартовой страницы допустим только доступный включённый раздел; при входе
право проверяется повторно. Перенесённые страницы ведут на новые маршруты,
остальные — на legacy. Без подходящей страницы сохраняется прежний /enterprise.
Version20261011190000 добавляет start_page_id и счётчик новых ID. Команда
legacy:import-identity --start-pages-only переносит только didDefault, не заменяя
пользователей, права и сессии; полный импорт также учитывает didDefault.
Таблица компактная, по содержимому, с логином и ролью. Фильтр «Скрыть неактивных»
включён по умолчанию; hideInactive=0 показывает отключённых пользователей.
Лимит сессий отсутствует в списке, форме и DTO. Сохранение прав не изменяет
существующий лимит, в том числе при передаче maxActiveSessions вручную.

HTTP-тесты: сохранение/CSRF/раздельные права/неизвестные значения, запрет входа без роли,
отзыв действующих сессий. Unit-тесты проверяют все известные роли и fail-closed для
неизвестных. Старые тесты сессий, меню и платежей остаются частью регрессии.

2026-10-11: PHPUnit переведён с рабочей monolit_app на отдельную monolit_test.
У тестового пользователя БД нет прав на рабочую базу; bootstrap дополнительно
блокирует запуск с URL другой базы. Тестовые пользователи не попадают в рабочий UI.
