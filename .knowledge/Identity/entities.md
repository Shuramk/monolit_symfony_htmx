# User и авторизация

`App\Domain\Identity\Entities\User` — Doctrine-сущность на существующей таблице
`identity_users`, одновременно UserInterface и PasswordAuthenticatedUserInterface.
Старый `Security/IdentityUser` заменён, второй модели пользователя нет.
Все поля таблицы, legacy ID, группа/привилегии, nullable-хеш/дата его обновления,
enabled и даты отображены. Argon2id и импортированные хеши сохранены.

`UserRepository` использует EntityManager и EntityRepository с QueryBuilder:
findById(), findByLogin(), save(). Загрузка обновляет identity map через HINT_REFRESH:
между запросами нельзя сохранять устаревшие enabled/хеш/имя пользователя.
`IdentityUserProvider` делегирует загрузку/refresh репозиторию; supportsClass учитывает
подклассы User (Doctrine proxies). Security, checker, voter, подписчики входа/выхода,
Twig и автоматический resolver аргумента контроллера используют сущность User.
В контроллерах нет запросов в БД. Права пока остаются в существующем механизме.

## Лимит и время жизни сессий

- User::DEFAULT_MAX_ACTIVE_SESSIONS = 1 — значение по умолчанию. Поле
  User::$maxActiveSessions / identity_users.max_active_sessions задаёт индивидуальный
  лимит. Для изменения: setMaxActiveSessions(3) и UserRepository::save($user).
  Допустимы значения 1–32767 (диапазон SMALLINT); специальных правил для отдельных логинов нет.
- User::SESSION_IDLE_TIMEOUT_SECONDS = 60 * 60 — время бездействия. Используется
  IdentitySessionRepository при входе и продлении активности, а также в framework.session.gc_maxlifetime,
  чтобы PHP-сессия не собиралась раньше настроенного таймаута.

Все вкладки одного браузера используют одну сессию. При заполненном лимите новый
вход вытесняет самую давно созданную сессию (created_at ASC, при одинаковой секунде
token_hash ASC). При лимите 1 это прежнее поведение: новый вход заменяет старый,
старый браузер перенаправляется на login при следующем запросе. Истёкшие
сессии освобождают место при следующем входе, cron для этого не нужен. Каждая сессия
имеет независимый скользящий таймаут 60 минут: активность одного браузера не
продлевает жизнь другого. Выход удаляет только текущую сессию.

IdentitySessionRepository::register() выполняет транзакцию с FOR UPDATE на строке
пользователя и актуальным locking read сессий: два одновременных входа не обходят
лимит даже при первоначально пустой таблице сессий. Лимит читается из БД под блокировкой,
а не из устаревшего сериализованного User. Удаление старых записей и вставка новой
атомарны. Если лимит уменьшили ниже текущего количества, при следующем новом входе
вытесняется столько старых сессий, сколько нужно для соблюдения нового лимита.

SingleSessionLoginSubscriber регистрирует сессию на LoginSuccessEvent с приоритетом
-100: после всех проверок авторизации и штатной миграции PHP session ID.
Неверный пароль или другие ошибки авторизации НЕ вытесняют существующие сессии.
Раннее резервирование, rotate и SessionLimitReached удалены после возврата политики
вытеснения по решению пользователя. Повторная регистрация того же ID не занимает
новое место и не меняет дату первоначального входа.
LogoutSubscriber выполняется раньше штатной инвалидизации PHP-сессии Symfony.

Миграция Version20261008120000 добавляет индивидуальный лимит (всем существующим
пользователям 1) и меняет PK identity_user_sessions на (user_id, token_hash), сохраняя
существовавшие записи. Применена локально к monolit_app; legacy не изменялась.
Down откажется выполняться при нескольких записях на пользователя, чтобы не удалять их.

После выкладки переименованного класса пользователя старая сериализованная сессия
может потребовать повторного входа. Старый класс/compatibility alias не оставляли.
Авторы и менеджеры заказов пока остаются scalar ID: отсутствующих legacy-пользователей
нельзя потерять добавлением неподготовленных FK.

## Проверки

UserMappingTest: точное сравнение таблицы с ORM, сохранение/чтение, Security-интерфейсы,
сериализация/refresh и актуальность disabled/хеша/имени. IdentitySessionRepositoryTest:
вытеснение старейшего входа, индивидуальный лимит и его уменьшение, независимый
выход/таймаут, освобождение истёкшего места и конкурентный вход двумя отдельными
PHP-процессами (оба входят, остаётся одна сессия).
LoginControllerTest: Argon2id-вход, POST/CSRF-выход, запросы одной сессии, замена другим
входом без взаимного разлогинивания, три браузера/вытеснение первого четвёртым,
освобождение места при выходе, сохранение старой сессии при неверном пароле,
истечение, отключённая учётка и неправильный пароль. Middleware/voter тесты
проверяют получение User по типу и сохранение проверок прав.
