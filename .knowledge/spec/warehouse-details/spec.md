# Детализация склада: перенос legacy 104/105/106

Источник истины: monolit_old/templates/parent_products.tpl, modules/admindirector.php
104–106, classes/Products.class.php, Tasks.class.php, modules/materials.php.
Legacy только для чтения. Новые операции и журналы только в application.

FR1: прежние колонки, размеры, чередование строк, нумерация и ссылки.
Склад в скобках = Офис + Цех + сохранённый третий склад − открытые задачи
на отгрузку type=2/status=0. Это не свободный остаток минус все заказы.
В заказах = неотгруженное в new/in_progress/ready_for_shipment/partially_shipped.
В переложке = выработка с Quantity и без ssUserID. Popup показывает заказы/задачи.

FR2: Добавить/Списать с выбором склада, количеством, комментарием;
при добавлении опциональные смена и дата. Одна транзакция, блокировка товара,
идемпотентный ключ отправки, неизменяемый журнал, без изменения цен заказов.
Выработка: код смены 111 (литье), 211/212/221/222 (прессы).
Сырьё: recipe_quantity / recipe_output * produced / material_ratio,
только production=1, округление до 3 знаков, дата изготовления 23:59:00.
Нет рецепта: сохранить приход, показать предупреждение, как действующий legacy
(ограничение рецепта в старом обработчике закомментировано). Нулевой выход
или некорректная единица рецепта: откат вместо повреждения бухгалтерии.
Предупреждения о смене/форме не запрещают операцию, как в legacy.

FR3: история товара с пагинацией, актором, сменой, датой, складом,
количеством и комментарием. Min: сохранение blur/Enter, только группа 1.
FR4: потребность max(0,min − Цех + в задачах − в переложке), выбор строк,
печать и постановка производственных задач с выбором пресса.
FR5: производственные задачи: остаток задания, частичная выработка,
приёмка из переложки в склад с журналом/сырьём; нельзя принять дважды.
FR6: импорт задач/карточек, выработки, истории, сырья, рецептов, балансов,
табеля и форм. Сохранить исходные поля в JSON; serialized массивы только
unserialize allowed_classes=false → JSON. Импорт однократный, атомарный,
не удаляет application products/orders/users. Повтор — no-op.

Права: просмотр division101; операция division106 + группы1/3 или user31;
списание и min только группа1; Офис/Цех показываются группам1/2.
Общий CSRF, RequestDtoResolver, User по типу. SQL только в репозиториях.
Не переносим соседние разделы управления сырьём/табелями/кассами: здесь
сохраняются их данные и связанные эффекты складской операции.

Тесты: разделение отгрузочных задач и заказов, дубли строк/отгрузок,
отключённые цвета, третий склад, пустые задачи, идемпотентность, границы,
сырьё/смены, отказ прав/CSRF, откат, выработка/повтор приёмки, HTTP/JS/печать.
