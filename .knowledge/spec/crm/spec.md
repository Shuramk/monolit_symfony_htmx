# CRM без чата

Дата: 2026-10-12. Источники: legacy customerRequest.class.php, CRMTasks.class.php,
route_orders.php (1700–1759), requests.tpl и crm_tasks/*.tpl.

## Объём

Сделки: список, фильтр менеджеров, создание/редактирование, клиент, товары,
бюджет/БН/ФОП, источник клиента, укладчик, даты, адрес, комментарии,
следующий контакт и история; отмена с причиной, скрытие/восстановление,
отменённые сделки, перевод сделки в заказ. Звонки/посетители.
Задачи: себе/от себя, исполнители/соисполнители/наблюдатели, сроки, комментарии,
история, уведомления, выполнение/возврат/отмена/скрытие, вложения и архив.
Директор: та же модель задач, все сотрудники и все архивные задачи.
Чат и изменение статуса заказа здесь не реализуются: к заказам возвращаемся после CRM.

## Дополнение: кнопки и продукция сделки

- Сохранить, новый пустой заказ (отдельная вкладка), отмена с причиной и перевод
  сохранённой сделки в заказ сохраняют свои текущие серверные проверки.
- Счёт доступен для сохранённой неотменённой сделки с продукцией и НДС/ФОП;
  коммерческое — с продукцией. Оба скачиваются в DOCX из app, без обращения к legacy.
- Строки: группа, цвет/вариант, количество и единица, цена, цена с НДС/ФОП,
  скидка, сумма и удаление. Расчёты переиспользуют форму заказа.
- Сервер сохраняет конечную цену после скидки (4 знака), как legacy; отдельная
  скидка не требует новой колонки. НДС/ФОП применяется один раз.
- Отключённая ранее выбранная продукция остаётся видимой в существующей сделке.
- Итоги и бюджет обновляются при изменениях. Пустая продукция допускает ручной бюджет.
- Документы содержат реквизиты выбранного типа предприятия, клиента, продукцию,
  цены/количества/суммы и НДС. Данные читаются из сохранённой сделки.

## Архитектура

legacy (SELECT) → ImportLegacyCrm → crm_* в app
HTTP → Controller/Crm → DTO → UseCases → Entities + Repository → app
GET → ReadModel → Repository → Twig
Сделка → CreateOrder (одна транзакция) → orders + связь converted_order_id.

## Контракты

- /crm/deals: GET список, POST создание. /crm/deals/new: GET форма.
- /crm/deals/{id}: GET/POST карточка; /{id}/{cancel,hide,restore,convert}: POST.
- /crm/counters: POST атомарное увеличение calls/new_calls/visitors/new_visitors.
- /crm/tasks: GET личные задачи. /crm/tasks/archive: GET архив.
- /crm/director/tasks и /archive: GET все задачи с фильтрами и пагинацией.
- /crm/tasks/new, /crm/tasks/{id}: GET формы; POST сохранение.
- /crm/tasks/{id}/{complete,reopen,cancel,hide,restore}: POST действия.
- /crm/tasks/{id}/files: POST upload; /files/{file}: GET download, POST remove.
- Все записи CSRF, идентификаторы числовые, устаревшая version отклоняется.
- Сделки требуют 1700, создание 1701; задачи 1750/1751, архив 1754;
  директор 1755/1756/1759. Участники проверяются также на сервере.
- Обычный пользователь видит только свои/назначенные/наблюдаемые задачи;
  выполнять могут исполнители, отменять автор, скрывать/комментарий директора — Главная.
- Новые ID AUTO_INCREMENT выше импортированных; soft-state вместо удаления истории.
- Денежные значения Decimal, количества 3 знака, цены 4 знака, без float.
- Небезопасный HTML старого журнала выводится как обычный текст;
  unserialize только allowed_classes=false. Файлы вне public, случайные имена.

## Модель данных

crm_deals, crm_deal_items, crm_deal_contacts, crm_deal_history;
crm_tasks, crm_task_participants, crm_task_history, crm_task_notifications,
crm_task_files; crm_counters; crm_imports (маркер одноразового импорта).
Индексы по состоянию/сроку/автору/исполнителю и FK на CRM-родителей.
Legacy-ссылки на удалённых пользователей/клиентов не теряются: справочники LEFT JOIN.
Конверсия хранит связь, не удаляет сделку, повторная конверсия возвращает тот же заказ.

## Проверки

Импорт полный/повторный/откат, legacy read-only; CSRF и доступ к чужим записям;
пустые/некорректные данные, Decimal, неизвестные справочники; конкурентные версии;
создать→редактировать→отменить→восстановить; выполнить→возврат→архив;
выбор участников/уведомления; конверсия в заказ без двойного создания;
файлы path traversal, отсутствие файла, размер и права скачивания.
