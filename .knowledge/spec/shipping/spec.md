# Задачи на отгрузку

Перенос этапа заказа: создание, список активных/выполненных, редактирование,
удаление активной задачи, отметка «Собрано», согласование, выполнение.
Legacy: Tasks::add_task_shipping/close_task_shipping/edit_task_shipping,
order_create_shipping_task.tpl, ship_task_list.tpl. Чат и перемещения вне этапа.

SQL только в Repository; HTTP → DTO → UseCase; GET → ReadModel → Repository → DTO.
Все записи только app; legacy читается при переносе перевозчиков.

Права: список 305, архив 311, форма создания 220+232, запись 220+310,
редактирование 307+309, удаление 308, выполнение/сборка 306 и роль
Главная/Производство (либо legacy пользователь 31). Согласование — право CRM 1700,
как в уже перенесённой CRM. Сборка и согласование независимы; legacy не запрещал
выполнение несогласованной/несобранной задачи, новые запреты не вводим.

Создание из заказа: позиции, остаток к отгрузке с учётом активных задач,
склад Офис/Цех, перевозчик/самовывоз, стоимость, дата/время, комментарий.
Количества точные (3 знака), нулевые строки пропускаются, пустой состав запрещён.
Товар должен принадлежать заказу. Повторяющиеся позиции заказа агрегируются.
Нельзя планировать больше неотгруженного и незапланированного остатка.

Выполнение: одной транзакцией блокируются заказ, задача и товары по ID;
списываются реальные остатки выбранного склада, добавляется warehouse_history,
order_shipments/items, меняются статус задачи и статус заказа, пишется история.
Статус: частично отгружен / доставлен / оплачен и доставлен по факту; нулевая
стоимость с нулевой оплатой считается оплаченной. Отрицательный склад разрешён,
как в legacy; предупреждение в UI. Повтор/устаревшая версия не списывает повторно.
Завершённую задачу нельзя изменить или удалить. Импортированные перемещения
без заказа показываются, но их выполнение относится к отдельному workflow.

Схема: version, operation_key в warehouse_shipping_tasks; справочник shipping_carriers;
последовательность ID отгрузок; индекс order_shipments(task_id).
Перевозчики импортируются INSERT IGNORE; существующие записи не перезаписываются.
payload старых задач сохраняется; новые поля совместимы с CRM/складскими резервами.

Проверки: права/CSRF, валидация, создание/редактирование/согласование/сборка,
обе локации, частичная и полная отгрузка, повтор, stale, отменённый заказ,
изменение резерва, архив/пагинация, атомарность и отсутствие legacy-записей.
