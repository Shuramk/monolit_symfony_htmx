# Смена статуса и отмена заказа

Дата: 2026-10-13. Источники: legacy route_orders.php:229,
Order::chg_order_state(), customerRequest::copyRequestFromOrder(), order_in_detail.tpl.

## Границы

В этом этапе: ручная смена статуса, отмена с причиной, история и отменённая
CRM-копия. Следующий этап — задачи на отгрузку; чат не затрагивается.

## Контракт

POST /orders/{id}/status, DTO: status (OrderStatus), version (>=0), comment.
Права 220 и 229, CSRF. Изменение под блокировкой заказа, version проверяется
перед записью. GET не меняет статус и не создаёт CRM-записи.

HTTP → DTO → ChangeOrderStatus → OrderRepository + Order + CRM use case
GET → OrderDetailsView → OrderViewRepository → DTO → Twig.
SQL только в репозиториях, контроллеры не собирают данные вручную.

## Правила

- Все существующие статусы; «Оплачен и доставлен» вручную — только Главная.
- Отмена запрещена при положительных оплатах (включая доставку) или записях отгрузки.
- При отмене причина обязательна. Заказ и его финансовая/складская история не удаляются.
- Создаётся отменённая сделка с клиентом, позицией/ценой/количеством, БН/ФОП,
  бюджетом без доставки, первоначальной датой и автором заказа; контакт с причиной
  без исполнителя; исходная история копируется, причина записывается отдельно.
- source_order_id в crm_deals — nullable индексированная ссылка на исходный заказ.
  Новая отмена после восстановления заказа создаёт новую копию; старые копии не меняются.
- Устаревший повтор POST отклоняется без повторной копии. Текущий статус — no-op.
- Повторяющиеся товары агрегируются по количеству и средневзвешенной цене;
  исходные строки остаются в истории. При потерянном product_id отмена откатывается
  с просьбой восстановить связь продукции: данные не теряются молча.
- Если нет права CRM 1700, после отмены пользователь остаётся в карточке заказа.

## Схема

Add-only migration: ALTER TABLE crm_deals ADD source_order_id BIGINT DEFAULT NULL;
CREATE INDEX IDX_CRM_DEAL_SOURCE_ORDER ON crm_deals (source_order_id).
Down удаляет только новый индекс/поле. Legacy — только чтение.

## Проверки

Права/CSRF, версия, все статусы, ограничения роли, оплата товара/доставки,
отгрузка, обязательная причина, атомарная CRM-копия, источник/история,
повтор/no-op, восстановление, НДС/ФОП/бюджет, GET без записи.
