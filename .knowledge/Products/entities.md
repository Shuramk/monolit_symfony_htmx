# Product: Doctrine-сущность

`App\Domain\Product\Entities\Product` отображает существующую application-таблицу
`products`, включая все поля, точность DECIMAL, nullable-колонки, индексы и даты.
ID задаётся явно и совпадает с legacy ID; GeneratedValue нет.
Миграции, импорт и изменение данных для перехода не нужны. Legacy не изменяется.

В одной таблице находятся группы и варианты (цвета): `parent` — nullable ManyToOne
на Product, `variants` — OneToMany, сортировка sorting/id, существующий FK SET NULL.
Каскадной записи/удаления продукции нет. Цена предоставляется через Decimal (scale 4),
в БД остаётся DECIMAL(12,4). Конструктор создаёт группу или вариант, инициализирует
коллекцию, timestamps и значения по умолчанию. Сеттеров на будущее не добавлено.

## Репозитории и заказы

- ProductRepository: EntityManager, getById(), getByIds(). Последний загружает все
  запрошенные ID одним запросом, возвращает array<int, Product>, повторные ID
  убираются; отсутствующие пропускаются, пустой массив не выполняет SQL.
  Репозиторий не фильтрует доступность. Order проверяет isAvailableForOrder()
  при сборке новых позиций: для заказа нужен активный вариант, при редактировании
  нового товара — также активная группа. Создание сохраняет requireActiveParent=false.
  Родитель читается fetch-join, актуальность ORM identity map обновляется HINT_REFRESH.
- ProductCatalogRepository: остаётся DBAL read repository для каталога, форм,
  расширенного поиска заказов. Возвращает DTO/массивы; ORM туда не внедряется.
- CreateOrderDto.products / UpdateOrderDto.products содержат array<int, Product>,
  заполняются заново use case через getByIds(array_column(lines, 'productId')),
  не доверяют ранее переданному обогащению. Нет поштучных запросов в цикле.
- OrderItem.product: ManyToOne по существующему product_id, nullable, ON DELETE SET NULL,
  без cascade persist/remove. Снимок названия, группы, единицы и цены остаётся в позиции.
  Изменение справочника не изменяет прошлый заказ. Неизменившийся товар при редактировании
  сохраняет старый снимок, включая отключённый/удалённый товар.
- OrderItemData содержит Product|null и productSnapshot; null допускается только
  вместе с историческим снимком. getProductId() теперь получает ID из связи.

Отгрузки этим изменением не затронуты; их product_id пока остаётся прежним.
Импорт products не запускался: его существующий DELETE опасен для живых FK-ссылок,
не использовать для повторного наполнения поверх работающих заказов.

## Проверки

ProductMappingTest проверяет чтение существующего каталога, parent/variants,
точное совпадение маппинга Product с реальной таблицей через DBAL Comparator
(без прикладных schema-listener и без применения SQL),
ManyToOne позиции, ORM-сохранение нового товара с точной ценой, удаление с SET NULL
и сохранением снимка, отключённые группы/варианты и bulk-загрузку. Изменения тестовых
данных выполняются в транзакциях с rollback.
Существующие OrderTest, HTTP-сценарии создания/редактирования и тесты changelog
проверяют прежние правила, исторические снимки, ошибки и откат общей транзакции.
Регрессионный тест создания с двумя товарами и повторяющейся позицией проверяет
по SQL-профайлеру ровно один SELECT products, включая загрузку родителей.
Unit-тесты Order отклоняют загруженные, но отключённые новые товары/группы.
